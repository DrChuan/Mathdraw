| 位置 | 用途 |

## 2. 启动

### 日常运行当前源码

Mac 双击 `数学绘图/启动数学绘图.command`；Windows 双击 `启动数学绘图.cmd`。根目录命令等价入口：

```sh
cd /Users/chuan/ChuanAILab
npm run drawing
```

入口调用 `scripts/launch-drawing.mjs`：

1. 通过 `local-drawing.mjs` 对源码、配置和资源计算指纹。
2. 与 `.build-cache/local-drawing-build.json` 比较；无包或内容变化时重建。
3. 本机构建临时关闭 updater 签名产物要求；Mac 目标为 Universal，Windows 构建 NSIS。
4. 完整包通过后替换 `产物/Mathdraw.app` 或 `mathdraw.exe`，保留前一个本机应用副本，再启动。

第一次或变更后等待编译是正常现象。**构建了新包不代表正在运行的旧进程已更新**。用户应正常退出、处理未保存内容后再打开入口，不要直接强杀。

### 开发热更新

```sh
cd /Users/chuan/ChuanAILab/枝间
npm ci
npm run drawing:dev
```

这是 Tauri 开发窗口，内部使用 Vite 127.0.0.1:1420，不是交付成浏览器应用。`npm run desktop` 打开笔记版；两者不要误用。

Mac 环境需要 Node、Rust/Cargo、Apple Command Line Tools 和 SDK。构建通用版还需要：

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
```

Node 版本以锁文件与当前依赖要求为准；现有 Windows 脚本检查至少 22.12，当前 CI 使用 26。

## 3. 检查命令

在 `枝间/` 下，根据本次授权和改动范围执行：

```sh
# 类型检查 + 前端生产构建
npm run build

# 绘图相关自动检查
npx vitest run src/drawing

# 精确求解相关定向检查
npx vitest run src/drawing/constraints/exactSystem.test.ts src/drawing/constraints/exactGeometry.test.ts

# 全工程前端检查，包含共享表达式解析与笔记相关测试
npm test

# 原生层单元检查
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

改共享表达式、主入口、Rust 菜单或文档协议时应考虑笔记版回归。测试数量会随源码变化；报告要写清命令、范围、时间及是否本轮真正执行。

### 原生检查原则

- 用户现有窗口可能有未落盘文件、未完成表达式或条件草稿，不因“程序显示已保存”就当成全部可丢弃。
- 桌面隔离检查使用不同 productName / identifier / 恢复目录；注意 Rust 对独立版标识的判断，测试菜单未必覆盖正式菜单。
- 自动审批若阻止启动或退出，明确记录已完成部分和阻止原因，不换成间接方法绕过。
- 前端构建、Mac 交叉编译、Windows 虚拟机启动、Windows 实机验证是四种证据，不能互相代替。

## 4. 仅打包，不发布

### Mac 本地无签名更新包构建

日常首选启动器。需要手工构建时，在 `枝间/` 下：

```sh
npm run bundle:drawing -- --target universal-apple-darwin --bundles app --config '{"bundle":{"createUpdaterArtifacts":false}}'
```

输出在 `src-tauri/target/universal-apple-darwin/release/bundle/macos/Mathdraw.app`。该构建不生成正式签名更新产物，不能直接当成正式在线更新发布。

### Windows 本机

需要 Node、Rust MSVC 目标、Visual Studio Build Tools 的 C++ 桌面工具和 Windows SDK。运行时需要 Microsoft Edge WebView2 Runtime。

```powershell
cd 数学绘图
.\scripts\build-mathdraw-windows.ps1 -UnsignedDevelopment
```

正式签名更新包按脚本要求提供原更新签名私钥；`-SkipInstall` 仅适合依赖已经按当前锁文件安装的情况。`-IncludeNotes` 会扩展到笔记应用，需同时考虑其签名配置。

输出 `数学绘图/产物/windows/`：安装 EXE、独立 EXE、签名（正式构建）及 `build-info.json`。独立 EXE 不是完全自包含运行时，分发给缺少 WebView2 的系统可能不能运行。

细节见 [Windows 打包说明](../scripts/README-windows-packaging.md)。

## 5. 正式一键发布

**仅在用户明确要求发布时运行** `数学绘图/发布Mathdraw.command`。

- 选择升级第一/第二/第三位版本，或继续上次未完成发布。
- 脚本先检查工具、权限和既有 Release，再同步更新 npm、Cargo 和 Tauri 版本文件。
- Mac 机器构建 Windows x64（cargo-xwin）和 Mac Universal，生成签名与清单。
- GitHub 先草稿上传、校验，再公开；Gitee 镜像同一套文件，匿名下载校验后最后更新 latest.json。
- 发布成功后更新本机产物。不会自动替用户提交/推送当前全部源代码，也不自动运行测试。

### 脚本职责

| 文件（`数学绘图/scripts/`） | 职责 |
| --- | --- |
| `release-mathdraw.mjs` | 前置检查、版本同步、构建、压缩、发布、本机替换、续作 |
| `release-tools.mjs` | 缓存 LLVM / NSIS 的路径、依赖和启动包装适配 |
| `publish-mathdraw.mjs` | 验证包/签名/版本，生成清单，调 GitHub/Gitee |
| `github-release.mjs` | 通过认证 API 查找 Release，兼容草稿查询与续传 |
| `gitee-release.mjs` | Gitee Release、附件校验和镜像清单 |
| `setup-gitee-token.py` | 交互配置发布令牌，不把令牌写进源代码 |
| `build-mathdraw-windows.ps1` | Windows 本机打包 |

### 输出、签名和源

输出：`数学绘图/产物/releases/<版本>/`。

```text
Mathdraw_<版本>_x64-setup.exe      # Windows 安装与更新负载
mathdraw.exe                     # 独立程序文件
Mathdraw-<版本>-macOS-universal.zip
Mathdraw.app.tar.gz               # Mac 更新负载
相应 .sig、latest.json、latest-gitee.json、SHA256SUMS.txt
build-windows.log、build-macos.log、archive.log、publish.log
```

- GitHub：`DrChuan/Mathdraw`。
- Gitee：`liu_chuanning/mathdraw`，不是最初设想的 DrChuan 路径。
- 更新私钥默认在 `数学绘图/.build-cache/signing/mathdraw.key`，或由 `TAURI_SIGNING_PRIVATE_KEY` 指定文件路径。**沿用原密钥，不生成新密钥替换既有发布链**。
- Gitee 令牌保存在本机钥匙串服务 `lab.chuan.mathdraw.gitee-publish`，也支持 `GITEE_TOKEN`；不要读取/打印它来生成文档或日志。
- updater 签名与 Windows Authenticode、Apple 公证不是同一件事。既有流程不能被描述为已完成后两者。

### 自动更新

`UpdateNotice.tsx` → `updateFlow.ts` → Rust `drawing_check_update`：

1. 启动独立程序后后台查 Gitee，4 秒上限。
2. 没有新版本或失败时查 GitHub，8 秒上限，编辑区不等待网络。
3. 用户确认才下载；验签、保存恢复草稿，再安装重启。
4. Windows 传入当前 EXE 所在目录的 NSIS `/D=`，更新回该目录。路径权限、杀毒软件和占用仍可能导致安装失败，不能承诺任意目录均成功。

## 6. 常见故障定位

| 症状 | 检查位置 / 处理方向 |
| --- | --- |
| 修改源码但看到旧界面 | 源码指纹、应用路径、旧进程、多份同名应用；不要只看相同版本号 |
| 发布失败后版本已增加 | 用“继续上次发布”，不要再次升版本；先看对应版本日志 |
| 缺 makensis / clang-cl 或依赖库 | `release-tools.mjs` 和 `.build-cache` 工具缓存，避免误将缺依赖当业务编译错误 |
| xcodebuild / SDK 配置问题 | Apple Command Line Tools、`xcode-select` 与实际编译器/SDK；当前流程不强制完整 Xcode |
| GitHub 草稿查询 404 | 使用既有 `github-release.mjs` 的认证列表/ID 路径，不直接把网页/tag 404 判为不存在 |
| GitHub 成功、Gitee 失败 | 保留原签名包、续传镜像，不重新覆盖公开版本 |
| 源文件保存被拒 | 外部修改/哈希冲突；保留草稿后另存，不能取消哈希保护强行覆盖 |
| 条件预览旧结果覆盖新输入 | `useLiveConstraints` 修订号、inputKey、Worker 请求 ID 和最终确认版本检查 |
| 一拖动就破坏条件 | 对象归属/绑定、请求目标、参照、候选回代，不能把条件点降为自由点 |
| 精确优化后明显卡顿 | 先定位 Worker 求解、原始几何重算、采样、绘制或 `document.ts` 的同步证书验证，不能只调一个采样常数 |

锁文件可能由异常退出留下，但只有确认原进程确实不存在后才清理。不要为排错删除整个 `.build-cache`：它不只是可重下载的编译垃圾，还可能含唯一的签名密钥和工具链依赖。

## 7. Git 与迁移

本次工作区根目录和两个产品目录均没有 `.git`；发现 `.build-cache/repos/mathdraw/` 有缓存 checkout，但不应把它当成当前源工程。旧记录中远端源码曾使用 `apps/mindmap-notes/`，本地是 `枝间/`，不能无检查地整目录覆盖。

接到“推送代码”任务时先确认真实 checkout、remote、分支、目标目录映射和未提交内容。Release 附件发布成功不代表当前源码已经提交。`解析求解优化完整补丁.patch` 是可审查备份，不是自动需要重新应用的安装步骤。

新机器迁移代码需包含 lockfiles、配置、脚本、资源和示例。签名私钥、令牌及用户绘图另行安全迁移；不放进公共仓库或普通源码 ZIP。
