# 轨迹依赖优化（2026-10-24）

本次修改普通构造轨迹。条件体系轨迹仍由条件求解器维护，不因本次修改绕过条件校验。

## 改进

- 统一以对象稳定 ID 遍历传递依赖，包含点、线、曲线、数值及参数坐标引用。生成的边/顶点引用追溯所属对象；依赖闭包与依赖判断使用同一份图，按不可变文档缓存。
- `Locus(M,Q)` 中的 M 可以是中点、交点或坐标派生点。如果两点共享唯一的上游路径动点 P，自动扫描 P，保存的轨迹引用实际驱动点，反向拖动也调整 P。两个派生点不必互相直接引用。
- 有多个独立上游动点时提示直接选择要扫描的路径点，不擅自决定它们的联动方式。其他独立参数保持当前值。位置相同不代表有构造依赖，自由点也不会被赋予隐藏路径。
- 当前位姿中从动点因除零、相交消失等原因暂时失效，不再阻止创建轨迹；扫描其他有效位姿。主动点失效时避免直接读取不存在的坐标。
- 精确坐标组合支持多级数值对象引用及普通动态直线/线段/多边形边上的定参数点；数值表达式代入带括号，防止改变运算优先级。
- 交点依赖线段或射线时转用原构造数值采样，保留范围筛选，避免把无限支撑线当成有限路径。需要归一化方向的关联直线上的点也保持数值回退。
- 数值采样与反向拖动使用同一几何内核的轻量入口，跳过仅用于点外观的逐点关联检查；几何计算、分支和错误规则保持一致。
