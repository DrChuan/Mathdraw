# 条件作图与求解器接续说明

核对日期：2026-10-24。源码入口在 `枝间/src/drawing/constraints/`。详细精确后端变化参见 [解析求解优化进度](解析求解优化进度.md)；早期规划见 [计算逻辑与解析求解演进](按条件作图计算逻辑与解析求解演进.md)。

## 1. 三种问题，不能混成三维投影

| `ConstraintProblem.mode` | 界面与数据语义 |
| --- | --- |
| `spatial`（旧数据缺省也按空间） | 独立声明空间点、线、圆/椭圆、图形/几何体；保留放置和观察设置 |
| `plane` | 无坐标二维几何，独立声明，不自动导入画布；曲线声明先支持圆，排除全局平移/旋转 |
| `coordinate` | 把当前画布所有对象与依赖作为同一问题，已知/待求明确；保持现有坐标基准，不自动镜像或重定原点 |

平面问题实际用二维未知量求解，不先在三维求出再投影。有坐标模式的曲线范围、已知数值、派生关系必须保留，不能变成固定采样点或复制一份原图。

## 2. 常驻预览和修订调度

```mermaid
flowchart LR
  A[对象 / 条件草稿变化] --> B[useLiveConstraints 300ms 防抖]
  B --> C[useConstraintSolver 请求 ID / 取消]
  C --> D[constraint.worker]
  D --> E[solveConstraints / solvePlanar]
  E --> F[回代当前原始条件]
  F --> G[仅接受最新修订的有效预览]
  G --> H[放入绘图区 / 更新图形]
  H --> I[一次提交与撤销]
```

- 输入与最后有效结果分开保存。错误、矛盾、搜索未找到或超时，保留旧图并禁用最终确认。
- 已有坐标只当新计算的初始猜测，不变成暗含条件。优先保留最近构型和分支连续性。
- 当前自动预算约 2000ms，深入搜索 8000ms；Worker 外层还有预算 + 2500ms 的超时保护。
- 取消通过终止 Worker；旧修订不得覆盖新输入。Worker 内缓存和消元续算随 Worker 销毁而丢失，不是跨会话任务系统。
- 确认前检查主画布是否变化，防止过期预览覆盖后来编辑。取消条件窗口不写入主画布。

主要界面：`ConstraintWorkbench.tsx`、`PlanarConstraintWorkbench.tsx`；公共调度：`useLiveConstraints.ts`、`useConstraintSolver.ts`、`constraint.worker.ts`。

## 3. 问题协议与输入

- `types.ts`：`ConstraintProblem`、`Condition`、`PlanarContext`、`SolutionBranch`、`ConstraintResult`、`SolveRequest`。
- `input.ts` / `form.ts` / `statement.ts`：语法解析、完整输入字段、自然语言 + 数学陈述。
- `angles.ts`：角值/三角函数条件及多值角分支。
- `scalarRelations.ts`：普通边长和角的标量等式；`vectors.ts`：显式向量线性运算和点积。
- `angleSuggestions.ts`：按已有线段生成可点选的角。
- `configuration.ts`：配置 v1/v2 解析和文件接口。

注意现状：几何文档的对象依赖主要用稳定 ID；但 `Condition.refs` 当前仍是点名数组，`Positions` 也按条件点名索引，并非所有条件引用都已迁移成对象 ID。改名和有坐标导入需维护二者映射，不要把原计划中的“统一稳定 ID 引用”当成已经完全实现。

显示线段不等于固定长度约束；图形声明才展开相应的关系。普通 `AB+BC=2AC` 是长度式；显式 `vec(AB)` / `\overrightarrow{AB}` 才是向量。原始 source、精确系数源码及数值字段分别保留，不能仅凭浮点 value 推断原精确输入。

当前通常限制 50 个声明点、200 条条件/线段；有坐标文档有自己的对象读取范围。二维最多同时求解 100 个独立坐标分量或参数，不能以“导入了很多对象”推断全都成为未知量。

## 4. 求解路线

### 4.1 空间

`solver.ts` 是公共入口，先分流平面模式，空间路径处理问题校验、角多值、固定参照/拖动等特殊请求，再尝试以下路线：

1. **精确代数尝试**：`spatialExact.ts` + `symbolicGeometry.ts` 编译适用问题，由 `exactSystem.ts` 求解。当前空间尝试有 12 点门槛。
2. **专门解析构造**：`construction.ts` 的直棱柱等快速路径。
3. **通用构造规划**：`planner.ts` + `metric.ts` + `intersections.ts` + `incidence.ts`，传播距离/向量关系，将约束转成平面、球面等轨迹并求交。
4. **数值回退**：使用构造种子和旧构型，阻尼最小二乘及多起点搜索；用 `compile.ts` 对全部原条件和退化关系回代。

并非每个请求都严格走完以上四步：有限精确结果可直接返回，移动和参照请求有独立分支；超预算或无法精确翻译时继续保留旧构造与数值能力。

### 4.2 平面

- `planar.ts`：二维模型、求解、固定参照、拖动、调参和结果组织。
- `planarModel.ts` / `planarExpressions.ts`：保留原定义图，建立独立未知字段、求值、范围和原条件检查。
- `planarSymbolic.ts`：把原生对象依赖与几何条件翻译到精确源表达式。
- 优先新精确系统；兼容旧的有理表达式/代数候选及几何构造路线，最后数值回退。
- `algebraic.ts`、`quadratic.ts` 仍有作用，不能因为新增 `exactSystem.ts` 就直接删除。旧浮点候选不自动拥有新后端的穷尽认证。

## 5. 新精确后端到底做到了什么

| 文件 | 职责 |
| --- | --- |
| `exactArithmetic.ts` | BigInt 约分有理数、一元多项式、Sturm 实根隔离、有理区间与符号判定 |
| `exactSystem.ts` | AST 编译、根式辅助变量、定义域、线性降维、分块、Gröbner 消元、共同生成元、证书、缓存及续算 |
| `symbolicGeometry.ts` | 平面/空间共用几何约束编译，保留非零、符号与非退化条件 |
| `spatialExact.ts` | 空间规范坐标与源表达式入口，区分初始框架和拖动校验 |
| `planarSymbolic.ts` | 二维原文档依赖、参数与曲线/射线/范围翻译 |
| `exactDisplay.ts` | 优先显示保存的精确表达 |

`exactAnalysis` 记录 `finite/family/unresolved`、是否认证、数学解数、降维变量数、失败原因及连续族；`exactCertificate` 保存源约束、变量、辅助量、生成元多项式和有理隔离区间、坐标表达。

`document.ts` 加载时会验证证书与原条件、坐标和根对应性；认证完整性还要有可复核的枚举依据。改参或拖动走数值回退后，旧证书、精确根和完整性声明必须失效，不能只改小数坐标保留旧“精确”标签。

### 三个容易混淆的概念

1. **解析构造**：用几何公式/轨迹求交生成候选，可能仍用浮点计算。
2. **精确表示**：值保存为分数、根式或代数根信息，不等于已找到所有解。
3. **穷尽认证**：针对当前原约束证明所有有限候选及有效域筛选完备。`exactAnalysis.certified` 与旧构造路径的 `complete` 不能混读。

有限结果界面最多展示 12 个构型，不等于数学系统最多有 12 个解。新后端可在精确信息中保留更多候选；达到计算上限要标“未完成”，不能宣布无解或偷偷截断成完整。

### 当前能力边界

- 不是任意方程的 CAS：一般三角、指数、对数、无法合法消去的超越系数仍会回退。
- 非线性耦合块当前有 6 变量保护，精确组合默认上限 256；另有次数、项数、系数位数、操作数和时间预算。
- 并非任意对象、旋转参数、共球条件、自交多边形判定都已精确翻译；记录 unsupported/translation 原因，保留可行回退。
- 已保存参数/隐式连续族不等于实现了任意半代数集的全局连通分量和全部退化层参数化。
- `notFound`、超时、预算/规模上限、未支持翻译、已证明矛盾是不同结果。

## 6. 自由度与拖动

- `dof`：形状的构型自由度，空间与平面无坐标排除整图平移/旋转。有坐标模式则保留既定坐标和未知量语义。
- `motionDof`：当前固定参照下的可运动维数。固定更多点可以锁住运动，不应倒推形状本身已经多了数学约束。
- `mobility.ts`：局部一阶零空间及二阶半正定阻碍，处理相切、极值虚假自由度；高阶/复杂奇异情形仍保守。
- `shapeMobility.ts`：空间刚体轨道的横截面及共线时残余轴旋转，不能机械减 6。
- `reference.ts` / `rigidMotion.ts`：参照与驱动选择、保留参照的刚体候选运动。
- `useConstraintMotion.ts`：一次在途请求 + 可替换的最新鼠标目标；`constraintPending.ts` 协调保存/退出前的在途联动。
- `document.ts` 的绑定与安装保护：条件点看起来是普通点，也不能绕开整个解集单独更新。

移动时优先精确或构造联动，最近分支只是连续性偏好，不是允许违反条件。每个发布到主画布的位置都必须经过原条件验证；失败保留上一个有效位置。

## 7. 修改时应覆盖的情形

- 长度/角标量式与显式向量式不混淆；分数、根式、连等、特殊三角值保留语义。
- 共线、相切、重根、重合、镜像、共球不唯一及定义域/严格不等式边界。
- 单点/轴参照不产生刚性形状的虚假自由度；真的铰接仍能动。
- 换参照保留有效证书，数值拖动不保留过期证书；近邻根不按绘图容差误合并。
- 参数滑块、反向轨迹拖动、快速更新、取消和保存时的异步修订保护。
- 空间条件生成面的遮挡与稳定引用；平面有坐标更新不复制/丢失原对象。

数学扩展应落在公共编译、求交或精确运算层，而不是按点名、特定案例文件或某次截图添加分支。

## 2026-10-25：离心率参与待求参数的联立

旧版能在数值环境中求 `e(c)`，但未将其转换为精确代数条件。把半轴、直线参数、两个交点和面积混在一起搜索，初始半轴相等处又存在分支不光滑，默认预览时间内容易暂未找到解。手动写定椭圆后未知量减少，因此更易找到。

新增 `constraints/conicAlgebra.ts`：对一般二次方程保留符号系数，而不是代入初始值。设二次项为 Ax²+Bxy+Cy²，一次项为 Dx+Ey，常数 F，t=A+C，d=AC−B²/4，g=CD²−BDE+AE²−4dF。离心率 e 的代数关系为 d(2−e²)²=t²(1−e²)，并加入 e≥0、t²+d²>0、g²>0、gt(2−e²)≥0 的有效性与分支判据。支持平移、旋转、方程整体缩放，覆盖实非退化椭圆、双曲线和抛物线；排除虚椭圆、退化曲线及双曲线共轭分支。原始数值定义仍最终回代。

新增 `constraints/parameterBlocks.ts`：从符号系统识别不依赖待求点的数值参数连通分组。只使用已认证的有限子解；参数族不任意固定。各分组候选参与后续联立，结果必须满足原始完整问题。子参数精确并不意味着整题精确；后续数值联立继续标近似。

回归覆盖该椭圆的半轴、离心率、长轴、过给定点的割线、两交点及三角形面积，使用默认 2000 ms 预算，斜率和方向角两种直线参数化均取得回代通过的构型；同时覆盖上述各类圆锥曲线、负倍缩放、旋转、虚/退化曲线、双曲线另一分支及参数族不冻结。第一组相关回归共 135 项通过，随后追加两项检查后，离心率模块 17 项通过。未调用识别云端，未升版本或发布；Windows 与桌面人工交互未作本轮检查。

同轮补充：内置原点 `construction.type=origin` 原先缺少符号坐标，导致含 O 的面积等条件被标为不支持；现按其固定坐标系原点生成表达式，保持与几何解析器一致。新增断言确认该问题的符号转换无遗漏；最后相关二维约束 60 项检查通过。
