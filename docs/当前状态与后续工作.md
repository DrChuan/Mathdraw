### 条件作图常驻预览

记录：`枝间/LIVE_CONSTRAINT_PREVIEW.md`。

- 左输入、右常驻预览，取消“先输入完再开始计算”的必需步骤。

0.5.0 的本地发布说明即包含这次操作模式调整；不据此推断后续精确优化也已进入 0.5.0 安装包。

### 形状自由度

- `dof` 与 `motionDof` 分开；换固定参照不改变内在形状自由度。
- 排除整体平移旋转，处理相切/极值的二阶锁定。
- 共线构型还需排除残余绕轴转动，但保持共线的真实轴向变化不能误扣。
- 旧元数据由 `useConstraintMobility.ts` 后台刷新，保持坐标，不通过重建对象来修显示。

此前用户画面的四棱锥条件只固定 BC、AB、AD、PA 及部分垂直关系，C 仍能在底面内绕 B 移动；那个 1 是真实形状变化，不能为了显示 0 偷加矩形条件。

## 4. 已知边界与应优先评估的问题

1. **精确后端覆盖与退化分支。** 一般超越方程、任意派生定义、一般共球、任意半代数集连通分解仍未通用解决；不能宣传“所有高中题都精确可解”。
2. **完整性和证书的语义一致。** 旧 `complete`、新认证状态、数值更新失效、显示候选截断、文件恢复验证要一起看。
3. **主线程开销。** 大部分计算在 Worker，但文档/证书验证路径有同步精确复核；应测量其在复杂导入、确认和保存中的耗时，再决定迁移方式。
4. **交互连续性与性能。** Windows 曾被用户反馈卡顿；应区分几何求值、曲线采样、场景遮挡、React 重绘、Worker 往返和证书校验，避免凭感觉提高采样率。
5. **共享源工程的边界。** 主界面与求解文件已较大；后续可拆分，但必须保持对象操作统一、稳定 ID 和保存/撤销语义，不能并行维护第二套图形状态。
6. **平台实际验证。** 最新精确改动需要相应 Mac 操作检查、Windows 编译和实际运行记录；发布脚本成功不能代替它们。
7. **源码仓库的持续同步。** 本地目录不是直接 Git 工作树；历史远端有不同目录映射。明确源码提交与 Release 发布的独立流程，避免漏推或覆盖旧 checkout。
8. **自动预览失败诊断。** 继续区分输入错误、认证矛盾、未找到、超时、未支持；不能仅凭最大残差给某条条件定罪。

## 5. 后续工作的合理顺序

这不是自动执行计划，接手时结合用户的新任务选择：

1. 核对当前源码和未发布精确优化，先得到能复现的输入/文件与预期。
2. 数学错误优先落到公共表达式、约束编译、求交/精确求解和候选验证层。
3. 对精确后端新增能力做小而有代表性的回归，再按需验证主界面；不要只检查一张截图。
4. 扩展精确翻译与连续族/退化分解时同步维护证书和完整性依据。
5. 经用户要求才打包/发布；保留原启动器、原签名密钥和双源回退机制。

## 6. 产品与合作习惯

- 工具参考 GeoGebra、几何画板、Desmos 的直接作图和表达式联动，但交付仍是本地程序。
- 紧凑 UI、明确当前步骤、工具能先选点也能先选适用参考对象；高亮与吸附应符合当前工具要选的类型。
- 自动生成与手工生成对象表现一致；点圆点默认在交叉或单条线端点隐藏，其余应显示，并支持手工覆盖。
- 用户希望可以持续用 `启动数学绘图.command` 看到更新，而不是收 ZIP 手动替换。
- 不要反复打断询问常规实现选择。需要保护草稿或自动审批确实拦截时，说明具体来源、动作和原因。
- 用户要求“收尾”时停止扩大检查范围，完成必要落盘和状态说明；明确哪些尚未验证。
